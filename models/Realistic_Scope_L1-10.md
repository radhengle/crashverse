# Realistic scope: levels 1-10 + Daily Boss

Generated by `Tools/Blender/realistic/scope.py` from `origin/integration/v2` (`Assets/_Project/Resources/Data/chapter1.json`, `meta_v2.json` dailyBoss.layouts, `Layouts/*.json`).

## What the game actually references

* `LevelBuilder.Build` (Scripts/Level/LevelBuilder.cs) spawns **every layout block as a Unity cube** scaled to `s`, with `MaterialDefinition` from `mat` (wood / brick / steel). There is no per-level prefab or model lookup.
* `ArenaBuilder` builds only the island, pad, palms, clouds and cliff dressing (procedural). The island is **held**, so it is out of scope.
* `DailyBossRules.ForDate` picks one of `meta_v2.dailyBoss.layouts` (4 titan arenas), with materials wood/brick/steel. `titan_templates.json` arenas use the same 4 layouts.
* `GameSession.EnsureHeroSlot` loads `Resources/HeroBuildings/<heroSlot.fbx>`. Chapter 1 levels have **no heroSlot**, and OfflineMeta preview slots have `fbx=""`. So **no Bld_* hero building (Townhouse, Keep, Tower, Gate) is used by L1-10 or the Daily Boss**. The realism-test Townhouse stays as the reference asset only.
* `/workspace/crashverse/design` has only rulings/specs (no extra level files), and there is no `levels/` folder. Level data lives only in the layouts above.

So the realistic scope is the **material block pieces** the 14 layouts use, plus 2 dressed props (barrel decor, explosive crate). Each one maps to an existing BuildingKit module and is re-surfaced with the graded CC0 sets, using the kit v3.1 geometry and fracture.

## Mapping a block to a piece (for Developer)

* Each piece is authored at its kit size (Wall 3x3xt, Floor 3x3xt, Joint 0.3-0.4 x 3, Block 1x1x1, Roof 3.6x2.3). Scale it per block: `scale = block.s / piece.size` on the matching axes. Joint: the long axis goes to the block's longest axis. Wall: the thin axis goes to the block's thin axis.
* UV0 on every realistic piece is a **metric box projection** (`uv = position_m / tile_m` on the face's dominant axis). The textures are tiling sets, so after non-uniform scaling the UVs can be rebuilt from the scaled vertex positions with the same rule, and texel density stays constant. The tile size per kit is in `Kit_Real<M>_stats.json` (`tile_m`).
* Small dressing blocks (bell, flag, sails, lanterns, clock, sign, lamp, tank, wheel) are not separate models in the data. They use the material piece of their shape class (table above).
